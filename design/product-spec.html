On-Device EPUB Audiobook Generator

A privacy-first app that turns an EPUB into a listenable, chapter-aware audiobook—with dialogue attribution, distinct character voices, expressive delivery, and local audio export.

1. Product vision

The user imports an EPUB, reviews the book structure and detected speakers, chooses a voice style, and generates a complete audiobook without uploading the book or its text to a server.

Read the book

Parse EPUB chapters and reading order, clean up markup, preserve paragraph boundaries, and handle footnotes and front/back matter deliberately.

Understand who speaks

Identify dialogue, infer likely speakers from nearby narration, and track character identity across chapters.

Perform the text

Assign stable voices, infer restrained delivery cues from context, and synthesize speech in chapter-sized segments.

Deliver a real audiobook

Join segments, preserve chapter navigation, support resume playback, and export audio plus metadata.

Core feasibility note: fully on-device operation is a design constraint, not a guarantee that every device can run every model at high quality. Speaker attribution and emotional intent are probabilistic. The app should expose uncertainty, allow corrections, and use a model/device compatibility check rather than promising perfect interpretation.

2. Feature requirements

Import and book structure

  • Must Import a local .epub using the operating system file picker; never upload it.
  • Must Parse the EPUB container, package manifest, spine/reading order, navigation/TOC, XHTML, and CSS-relevant text order.
  • Must Split content into chapters and smaller synthesis segments while preserving paragraph order and sentence boundaries.
  • Should Handle common publishing patterns: chapter headings, epigraphs, block quotes, inline emphasis, footnotes, poetry, letters, and scene breaks.
  • Must Offer a preview of extracted text and let users skip or include front matter, footnotes, appendices, and end matter.

Text understanding and dialogue

  • Must Detect quoted dialogue and likely speaker turns, including dialogue tags such as “she said” and action beats.
  • Must Maintain a character/speaker registry across the whole book, not just within a paragraph.
  • Must Support ambiguous or unknown speakers and narration; do not force every line into a character voice.
  • Should Use surrounding context to infer delivery (questioning, whispering, shouting, sadness, excitement) with conservative confidence thresholds.
  • Must Provide an editor for correcting speaker labels, merging duplicate character entries, assigning voices, and overriding delivery.
  • Should Remember user corrections and apply them to later occurrences in the same book.

Speech generation and listening

  • Must Synthesize narration and dialogue locally using downloadable, locally stored model assets.
  • Must Keep character voices stable throughout a book, including pitch/timbre presets and pronunciation overrides where supported.
  • Must Generate incrementally, cache completed segments, and resume after app closure or interruption.
  • Must Include playback speed, skip forward/back, chapter navigation, sleep timer, and resume position.
  • Should Provide voice previews and a short sample render before committing to a full book.
  • Should Export chapter audio and a complete audiobook package with chapter metadata; format support depends on platform libraries.

On-device and reliability

  • Must After model assets are installed, book processing and synthesis work in airplane mode.
  • Must Show estimated storage, model download size, progress, remaining work, and thermal/battery warnings where available.
  • Must Provide low-memory behavior: smaller segments, sequential generation, cache eviction controls, and recovery from failed segments.
  • Should Offer model profiles such as Fast, Balanced, and High quality, subject to device capability.

3. End-to-end processing pipeline

  1. Import: open the EPUB locally and validate the archive and required files.
  2. Extract: read the spine in order, convert XHTML into structured blocks, normalize whitespace, and retain paragraph/chapter IDs.
  3. Normalize: expand or annotate abbreviations where useful, preserve punctuation and emphasis, and create sentence-aligned segments.
  4. Analyze: detect narration, quoted spans, dialogue tags, named entities, speaker candidates, and contextual delivery cues.
  5. Resolve characters: cluster mentions and speaker references into a consistent cast list; track aliases and pronouns with confidence scores.
  6. Review: show a cast sheet and uncertain passages; users can correct labels and choose voice assignments.
  7. Plan synthesis: assign voice, delivery, pronunciation hints, segment boundaries, and model settings.
  8. Synthesize: generate speech in manageable chunks; store audio and timing metadata locally.
  9. Assemble: normalize loudness carefully, add optional pauses between paragraphs/scenes, and write chapter boundaries and metadata.
  10. Listen/export: play from the library, resume reliably, and export supported audio formats.
Important separation: use one module for deciding what should be spoken and by whom, and another for turning the approved text/voice/delivery plan into audio. This makes the system easier to debug, test, and improve without re-parsing the entire book.

4. Character voices and expressive delivery

Voice assignment model

  • Start with a small, bundled or locally installable set of licensed voices.
  • Map each character to a stable voice profile; map non-character text to the narrator.
  • Allow a user to set narrator, character voices, voice gender/presentation where available, accent, pace, and expressiveness.
  • Use voice identity consistently. Emotion should usually be a delivery control, not a new voice identity.
  • Support an “unassigned” voice fallback when attribution confidence is low.

Inferring tone without overacting

  • Infer cues from explicit text first (e.g., “she whispered”), then use context for implicit tone.
  • Represent delivery as bounded controls such as pace, energy, softness, and pause length when the TTS model supports them.
  • Prefer neutral delivery when confidence is low; avoid making every line melodramatic.
  • Respect punctuation, italics, exclamation marks, and paragraph breaks, but avoid treating them as perfect emotion labels.
  • Allow global style controls such as “subtle”, “dramatic”, or “neutral” to scale inferred expressiveness.
Quality reality: realistic, expressive multi-speaker synthesis is the hardest dependency. Some compact models may be fast and private but less natural, less controllable, or less consistent. Benchmark actual candidate models on target devices before locking the product promise. Avoid cloning a real person's voice without clear permission and appropriate safeguards.

Platform strategy

Choose the first target platform early, because on-device ML acceleration, background execution, file access, audio export, and memory limits differ substantially. Keep parsing and orchestration portable where practical, but use platform-native inference acceleration and audio APIs. Do not promise identical performance across phones, tablets, and desktops.

Model selection checklist

  • License permits the intended app distribution and offline use.
  • Model size, RAM peak, cold-start time, sustained throughput, battery use, and thermal behavior are measured on target devices.
  • Supports required languages, punctuation, long-form stability, voice consistency, and controllable prosody.
  • Has an inference runtime compatible with the target OS and available hardware acceleration.
  • Can run without sending text, telemetry containing book content, or audio to a remote service.

6. Privacy, security, and content rights

  • Local by default: EPUB text, analysis, voice assignments, generated audio, and listening history stay on-device.
  • Explicit model downloads: network use is limited to user-approved model downloads, app updates, or optional non-content features.
  • No hidden upload: do not transmit book content, excerpts, generated audio, or character analysis for analytics or crash reports.
  • Safe EPUB parsing: treat EPUB files as untrusted archives; defend against path traversal, decompression bombs, malformed XML, and remote-resource loading.
  • User control: let users delete source books, generated audio, caches, and model assets independently.
  • Rights-aware messaging: remind users to use books they are authorized to process, and review copyright, DRM, and export rules for each launch market. Do not bypass DRM.
  • Voice rights: distribute only voices/models with suitable licenses and avoid deceptive impersonation.

Recommended first release boundary

Keep version one narrow: EPUB import, one high-quality narrator voice, reliable offline chapter generation, playback/resume, and a basic speaker editor. Add sophisticated character attribution and emotion only after measuring the quality of the local language-analysis and TTS models. This avoids making the entire app depend on several difficult AI problems being solved perfectly at once.

8. Acceptance tests

  • With model assets already installed, the app imports, analyzes, generates, and plays a test EPUB in airplane mode.
  • Chapter order and text order match the EPUB reading order; headings and paragraph breaks are preserved according to settings.
  • A failed or interrupted synthesis job resumes without regenerating every completed segment.
  • Users can correct a speaker assignment and hear the change in regenerated audio.
  • Character voice assignments remain stable across chapter boundaries unless the user changes them.
  • Ambiguous attribution falls back gracefully rather than confidently assigning the wrong character.
  • Long books can be processed without loading the entire text and all audio into memory at once.
  • Deleting a book removes its associated text/audio/cache according to the deletion options shown to the user.
  • Exported chapters play in order and include useful titles and chapter metadata where the chosen format supports them.
  • Automated tests include malformed EPUBs, huge compressed entries, unusual punctuation, nested quotes, dialogue without tags, poetry, and multiple languages.

9. Decisions to make before implementation

  • Target platform: iOS, Android, desktop, or cross-platform?
  • Device floor: what minimum RAM, processor class, and free storage are acceptable?
  • Languages: which languages and accents must work in the first release?
  • Model delivery: bundled models versus optional user-downloaded model packs?
  • Output formats: M4B with chapters, MP3, AAC, WAV, or another set? Support varies by platform and licensing.
  • Generation speed: is slower-than-real-time generation acceptable if quality is better?
  • Editing depth: should users edit speaker labels only, or also rewrite pronunciation and delivery cues?
  • Business/licensing: free/open-source models only, paid licensed models, or a mixed model catalog?

10. Short README

Project: On-Device EPUB Audiobook Generator

Goal: Convert an EPUB into a chapter-aware audiobook locally, with optional character-specific voices and contextual delivery.

Principles: privacy first, offline after model setup, stable voice identity, user-correctable AI decisions, resumable generation, and explicit model licensing.

Non-goals for the initial MVP: perfect automatic speaker attribution, real-person voice cloning, cloud processing, DRM circumvention, and guaranteed real-time generation on every device.

Build order: validate model feasibility → parse EPUB safely → generate narrator audio → add resumable playback/export → add speaker attribution and voice mapping → add expressive delivery.
